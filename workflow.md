# Workflow AI-Агента

Данный документ описывает общий процесс (флоу) работы AI-агента от получения требований до формирования итогового отчета.

## Общая схема процесса

1. **Получение требований**
   Агент получает входные данные (ссылку на страницу или текст) из Confluence.

2. **Этап 1: Анализ требований (Skill `requirement-review`)**
   Агент применяет Skill для анализа требований. На выходе формируется артефакт `ReviewReport`, содержащий список
функциональных требований, бизнес-правил, а также выявленные противоречия и неоднозначности.

3. **Этап 2: Прохождение Quality Gate (Проверка качества)**
   Агент проверяет артефакт `ReviewReport` на соответствие критериям (Quality Gates).
    - *Если найдены критические противоречия:* Агент останавливает работу и запускает процесс эскалации
   (Escalation Rules).
    - *Если проблем нет:* Агент переходит к следующему шагу.

4. **Этап 3: Параллельное проектирование**
   На основе прошедших проверку требований агент параллельно запускает два процесса:
    - **Skill `task-design`**: формирует задачи для Jira (артефакт `JiraTasks`).
    - **Skill `test-design`**: формирует тестовую модель для Test IT с позитивными, негативными и граничными 
   сценариями (артефакт `TestModel`).

5. **Этап 4: Валидация и сохранение результатов**
   Агент проверяет созданные артефакты (`JiraTasks`, `TestModel`) на соответствие JSON-схемам. 
Если всё валидно — сохраняет их в папку Artifacts.

6. **Этап 5: Итоговый отчет**
   Агент формирует итоговый отчет, в котором резюмирует выявленные проблемы (из `ReviewReport`) и результаты 
проектирования (созданные задачи и тест-кейсы). Отчет передается пользователю (человеку) для финального утверждения.
