# Skill: Task Design

## Purpose
Проектирование и декомпозиция проанализированных требований в задачи для команды разработки.
Skill предназначен для разбиения функциональности на логические компоненты (Epic, Story, Task), формулирования понятных описаний и критериев приемки (Definition of Done) для последующего создания задач в Jira.

## Inputs
- Проанализированные требования (прошедшие Quality Gate)
- Выявленные бизнес-правила и ограничения
- Выявленные зависимости
- Указание на проект в Jira (ключ проекта, тип задач)

## Procedure
При проектировании задач необходимо:
1. Определить общий объем работ (Epic) на основе крупного блока требований.
2. Выполнить декомпозицию Epic на User Stories (пользовательские истории).
3. Разбить Stories на конкретные Tasks (задачи для разработки/тестирования), если это необходимо.
4. Для каждой задачи сформулировать четкое название и описание.
5. Написать критерии приемки (Definition of Done) для каждой задачи.
6. Определить приоритет и зависимости между задачами.

## Rules
При выполнении проектирования задач необходимо соблюдать следующие правила:
- не создавать задачи, не имеющие основания в требованиях
- не создавать задачи без критериев приемки (DoD)
- не дробить задачи слишком мелко (избегать микроменеджмента)
- не объединять в одну задачу разную функциональность
- использовать единый формат описания задач (например, "Как [роль], я хочу [действие], чтобы [цель]")

## Output
Результат выполнения Skill должен содержать:
- Структурированный список задач (артефакт `JiraTasks`), готовый для импорта в Jira.
- Для каждой задачи: тип (Epic/Story/Task), название, описание, критерии приемки, приоритет, зависимости.

## Completion Criteria
Skill считается успешно выполненным, если:
- Все проанализированные требования покрыты задачами
- Каждая задача содержит четкое описание и критерии приемки
- Задачи не дублируют друг друга
- Задачи структурированы иерархически (Epic -> Story)
