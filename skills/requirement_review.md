## Purpose
Выполнять систематический анализ требований перед их использованием для формирования задач для разработки и проектирования тестовых сценариев.

Skill предназначен для выявления содержимого требований, их структуры и формата, неоднозначностей, противоречий, зависимостей и недостающей информации.

## Inputs
- текст требований
- связанные бизнес-сценарии
- критерии приемки
- ссылки на вложенные требования

Skill не может самостоятельно искать отсутствующие входные данные за пределами входного контекста.

## Procedure
При анализе требований необходимо:
- определить функциональные требования
- выделить бизнес-правила
- выявить ограничения
- определить критерии приемки
- определить зависимости
- выявить неоднозначности
- выявить противоречия
- выявить недостатки информации

## Rules
При выполнении анализа необходимо соблюдать следующие правила:
- не добавлять отсутствующие данные
- не выдавать предположения за подтвержденные требования
- не изменять требования
- не выполнять действия, не относящиеся к анализу требований

## Output
Результат выполнения Skill должен содержать:
- список выявленных функциональных требований
- бизнес-правила
- ограничения
- зависимости
- критерии приемки
- выявленные неоднозначности
- выявленные противоречия
- выявленные недостатки информации
- выявленные риски

Результат должен быть структурирован так, чтобы следующий этап мог его использовать без повторного анализа (в виде структурированного артефакта, например, JSON).

## Completion Criteria
Skill считается успешно выполненным, если:
- входные требования проанализированы
- бизнес-правила зафиксированы
- критерии приемки и зависимости определены
- все выявленные неоднозначности и противоречия зафиксированы в отчете
